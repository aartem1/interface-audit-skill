# Visual clarity and information design

Use this module for pages, documents, dashboards, and screens people need to understand at a glance or scan for an answer. It applies to read-only content and interactive views. Use the [main checklist](checklist.md) for rendering, accessibility, and behavior checks.

## Define what the reader needs

Before evaluating the layout, record the reader, entry point, and one primary purpose for the audited view. List the answer, facts, conditions, or actions needed for that purpose. If readers need to compare, name the entities, fields, and values they should be able to compare. For a longer page, list the topics readers may need to find independently. Record the source and any approved requirements for placement, terminology, or copy. If an inference would change a verdict, keep the check pending until the intent can be established. Layout, rendering, and other checks that can be decided without that intent can still run.

For a quick review, start with VIS-01 through VIS-05 and COPY-01 through COPY-02, then apply the format checks that match the page. Add VIS-07 when the page has a primary action. Use the initial viewport for VIS-01 and the full default reading view for VIS-02 and FMT-09. The default reading view includes content reachable by normal scrolling without opening a disclosure, switching tabs, hovering, or following a link.

The checks are evaluation rules derived from the cited guidance. A source may recommend a pattern without requiring it. Document any project-specific requirement or exception before testing. A static capture can confirm facts visible within its bounds. When a verdict depends on a state the capture does not show, use `not_checked`. Where the rule is about visibility in the captured default state, a complete capture of the relevant area can be sufficient.

## Choose a format for the task

Choose by the question the reader needs to answer. The table gives starting patterns. The checks below define the observable properties an equivalent pattern needs.

| Reader's task | Start with | Preserve |
| --- | --- | --- |
| Get one answer, status, or takeaway | A plain heading, a short answer, or one labeled value | Put any condition that changes its meaning next to the claim. |
| Read an explanation | Short prose under descriptive headings | Give the answer before its background and keep related text together. |
| Find one of several independent items | Bullets or a vertical list | Give each item its own scanning point. |
| Follow a sequence | Numbered steps or a visibly connected sequence | Make the next step and prerequisites clear. |
| Look up several facts about one item | Labeled rows or a summary list | Keep each value with its label. |
| Compare exact attributes across items | A table or a labeled comparison grid | Keep matching fields aligned in the same view. |
| Browse distinct articles, products, or destinations | A list or a collection of cards | Use an identifier and the details needed to tell items apart. |
| See a trend or relative magnitude | A chart suited to that relationship | Use a common reference for comparisons and provide exact values if the task requires them. |
| Read supporting details only when needed | A descriptive disclosure | Keep information required for the primary task visible alongside the content it qualifies. |
| Jump between independently useful sections of a long page | An outline or in-page navigation | Show the destination heading after the jump. |

Sources · [GOV.UK content structure](https://guidance.publishing.service.gov.uk/writing-to-gov-uk-standards/writing-guidelines/clear-structure/), [GOV.UK summary list](https://design-system.service.gov.uk/components/summary-list/), [USWDS cards](https://designsystem.digital.gov/components/card/), [GOV.UK tables](https://design-system.service.gov.uk/components/table/), [USWDS in-page navigation](https://designsystem.digital.gov/components/in-page-navigation/), [ONS chart selection](https://service-manual.ons.gov.uk/data-visualisation/chart-types/choosing-a-chart-type).

## Orientation and visual hierarchy

| ID · Check | Applies when | Test | Yes when |
| --- | --- | --- | --- |
| VIS-01 · The entry view identifies its purpose | A page or screen has a recorded primary purpose | Compare. Open the agreed entry state and read only the title and its associated text visible in the initial viewport. | That text names the subject and what the view provides or lets the reader do. A generic title can pass when an adjacent subtitle supplies the missing information. |
| VIS-02 · The primary content comes first | The view contains a recorded primary answer, data view, or start action plus supporting or promotional content | Compare. Locate those blocks in visual reading order in the default view. | The primary block appears before the first supporting or promotional block. A prerequisite needed to understand or use the primary block can appear before it. |
| VIS-03 · Section labels name the subject | The reader needs to locate two or more independent sections | Compare. Record the topic each section serves. Read each visible section label with its parent heading, without reading its body. | Each label identifies its section's topic or task and distinguishes it from its siblings. Labels that differ only by generic wording, such as “Overview” and “Details,” pass only when the parent headings resolve the actual subjects. |
| VIS-04 · Headings stand apart from body text | A heading introduces a section containing running text | Compare. Inspect the heading and first body line at each size under review. | The heading has its own line or region and a visible distinction from the body in size, weight, or an explicit separator. A color change alone is insufficient for this check. |
| VIS-05 · A label belongs to one visible group | A heading, caption, or value label lies between two adjacent content groups in the reading direction | Compare and measure. Identify the intended group and the nearest competing group in the same reading direction. Compare edge-to-edge gaps and visible boundaries. | The label and its content share a visible boundary that excludes the competitor, or the label is closer to its own content than to the competitor with no unrelated item between them. |
| VIS-06 · Reflow keeps dependent content in order | The brief or content establishes that one block must be understood before another, and the layout changes between sizes | Compare. Record the required order, then trace the visual reading order at each audited size. | The prerequisite appears before the dependent block in each audited layout. A different order passes when the dependent block includes the prerequisite inline. |
| VIS-07 · A primary action looks available before interaction | A task starts from a specific link or action in the view | Compare. Inspect the default state before hover, focus, tap, or click. | The entry action has a visible control shape, link treatment, or established platform affordance, and the action or destination is identifiable from its visible label or a conventional platform symbol verified for this use. |
| VIS-08 · Section jumps land on the heading | In-page links or an outline jump to sections | Run. Follow each selected link at the audited sizes with sticky UI in its normal state. | The linked section's heading or equivalent identifying label is visible after the jump, without further scrolling. |
| VIS-09 · Visual emphasis distinguishes priority | The brief calls for one peer block to receive more visual emphasis than another in the same view | Compare. Inspect both blocks in the same state. Record the title size and weight, enclosure, and any documented emphasis variant. | The primary block has a larger title, a heavier title at the same size, or a callout boundary or fill that the secondary block lacks. If the project specifies a different emphasis cue, compare that cue. |
| VIS-10 · Peer blocks share an alignment axis | At least two peer blocks occupy one row or one column and follow the same layout role | Measure. Compare the bounds of the equivalent content groups at each audited size. | In a row, peer blocks share their top edge or heading baseline. In a column, they share the same inline start. Use the specified axis and tolerance, or allow up to one logical display unit on the default axis. |

Sources · [NN/g visual hierarchy](https://www.nngroup.com/articles/visual-hierarchy-ux-definition/), [NN/g scanning by headings](https://www.nngroup.com/articles/layer-cake-pattern-scanning/), [GOV.UK content structure](https://guidance.publishing.service.gov.uk/writing-to-gov-uk-standards/writing-guidelines/clear-structure/), [NN/g icon usability](https://www.nngroup.com/articles/icon-usability/), [USWDS in-page navigation](https://designsystem.digital.gov/components/in-page-navigation/).

## Copy and typography

| ID · Check | Applies when | Test | Yes when |
| --- | --- | --- | --- |
| COPY-01 · The answer comes before its explanation | A text block answers a recorded reader question | Compare. Mark the first sentence or labeled line that answers the question and any earlier sentences. | The first sentence or labeled line gives the answer, or the immediate prerequisite for interpreting it. Explanatory background follows. |
| COPY-02 · Adjacent copy adds information | A summary and opening paragraph, or two adjacent explanatory blocks, cover the same topic | Compare. List the factual claims, qualifications, and actions in each block. | The later block adds at least one fact, qualification, example, or action. A brief restatement passes when the earlier block is a heading, caption, or label, or when a documented safety, legal, or accessibility need requires it. |
| COPY-03 · Required terms are explained at first use | A term or acronym is needed for the task and the audience profile or glossary identifies it as unfamiliar | Compare. Find the first occurrence in reading order for each supported entry point. | The first occurrence includes a plain term or a short definition in the same sentence or adjacent visible label. |
| COPY-04 · Running prose has a stable line start | A prose block wraps to four or more lines in the tested view and its writing system has an established inline start | Compare. Inspect the alignment of lines after any first-line indent. | The lines share the same inline start, left for left-to-right text and right for right-to-left text. A documented locale or publication convention can specify a different alignment. |
| COPY-05 · Long prose stays within the line measure | Body prose in a Latin-script language spans at least four soft-wrapped lines in the tested view, or the project defines a measure for the tested language | Measure. Count rendered characters, including spaces, on all soft-wrapped lines of the selected paragraphs. Exclude the final line and any unbreakable literal such as a URL. | The longest measured line stays within the project's stated limit, or 90 characters under this module's default for Latin-script prose. |
| COPY-06 · Prose serves an identified need | The page has an approved content plan specifying audience needs and required copy | Compare. Map each opening or standalone prose block to a named need or required item in the plan. | Each block contributes a fact, instruction, explanation, orientation cue, or required statement mapped to the plan. Flag only blocks with no such contribution. |

The four-line trigger and the 90-character maximum are operational defaults for this module, based on USWDS guidance for running prose. There is no minimum line length on narrow layouts. Use a stated locale-specific measure where available. Titles, captions, table cells, code, and short promotional taglines are outside COPY-04 and COPY-05. Sources · [GOV.UK content structure](https://guidance.publishing.service.gov.uk/writing-to-gov-uk-standards/writing-guidelines/clear-structure/), [GOV.UK clear language](https://guidance.publishing.service.gov.uk/writing-to-gov-uk-standards/writing-guidelines/clear-language/), [USWDS typography](https://designsystem.digital.gov/components/typography/).

## Lists, cards, tables, and charts

| ID · Check | Applies when | Test | Yes when |
| --- | --- | --- | --- |
| FMT-01 · Ordered steps show their sequence | Two or more reader actions must occur in a recorded order | Compare. Find each action and its place in the rendered instructions or sequence. | Each step is visually separate and numbered or connected in a visible progression matching the required order. |
| FMT-02 · Independent items have separate scan points | A reader needs to locate an individual item among three or more peers whose order is immaterial | Compare. Identify the items in the rendered content. | Each item has its own visible bullet, row, or equivalent separate block. |
| FMT-03 · Each value stays with its label | The reader needs to look up two or more named attributes of one entity | Compare. Trace each displayed value to its label at each audited size. | Every value has one unambiguous visible label in the same row, cell, or bounded group. |
| FMT-04 · Exact comparisons align matching fields | The reader needs to compare exact values for at least two named fields across at least two entities | Compare. Read matching fields for the selected entities on each audited layout. | The entities and their matching fields are available in the same comparison view and use the same labeled row, column, or aligned grid position. The reader can compare them without changing tabs, opening separate items, or remembering which field order each item uses. |
| FMT-05 · Each card identifies its item | A collection uses cards to help readers browse or choose distinct items | Compare. Read the top-level visible label of each card in the selection. | Each card shows an item name or identifier that distinguishes it from the other cards, together with any distinguishing attribute specified for this browse task. |
| FMT-06 · Repeated cards keep a stable field order | Cards for the same type of item repeat two or more named fields | Compare. Record the relative reading order of those shared fields in each card. | Shared fields appear in the same relative order across cards. An absent optional field can be skipped without reordering the remaining fields. |
| FMT-07 · Table values keep their visible context | An information table shows values whose interpretation depends on row or column headings or units | Compare. Locate each selected value and the applicable headers in the audited layout. Include the stacked or scrolled layout if offered. | The layout exposes the row and column labels needed to interpret the value, through visible headers or repeated inline labels. Required units are stated in those labels or alongside the values. For programmatic header relationships, use the W3C tables tutorial. |
| FMT-08 · Comparable numbers share a visual alignment | A table column shows comparable quantities using one format | Measure. Compare the horizontal alignment of the numeric text for at least two values of different lengths, with equal styling in the same column. | The numeric strings share an edge at the least significant digit side, or align at the decimal separator where present. |
| FMT-09 · Required conditions stay beside the claims they qualify | A verified condition changes how a primary claim, value, or instruction must be interpreted | Compare. Locate the claim and condition in the default reading view using the content inventory and rendered view. | The condition is visible in the same statement, row, or card group, or in a note immediately beside that group that identifies the claims it qualifies. It can be read with normal scrolling and without opening a disclosure, following a link, or switching views. |
| FMT-10 · A disclosure label tells readers what will open | A collapsed section contains optional detail | Compare and run. Read the trigger in context, expand it, and compare the result with the label. | The visible trigger or its associated heading names the subject of the content that opens. |
| FMT-11 · Exact chart values can be read directly | A chart is part of a task that needs exact values | Compare visible values against the reference data. If the values must be revealed, run the lookup with each input mode under audit. | The exact values are available through data labels, operable tooltips, a data table, or an equivalent data view. Estimating from a mark's position is insufficient. |
| FMT-12 · The chart shows the intended relationship | The primary chart task is to compare magnitudes or see change over time | Compare. Check the expected relationship against the encoding, scales, and ordered categories or dates. | For magnitudes, the compared marks share a scale and a comparison reference, such as the baseline for bars or an axis for dots. For change over time, dates or periods progress in order on the time axis or equivalent sequence, with the same measure traceable across periods. |

Three peers in FMT-02 and the two-entity, two-field trigger in FMT-04 are audit defaults that make selection reproducible. They do not define when a designer is allowed to use a list or table. Sources · [USWDS lists](https://designsystem.digital.gov/components/list/), [USWDS cards](https://designsystem.digital.gov/components/card/), [GOV.UK summary list](https://design-system.service.gov.uk/components/summary-list/), [GOV.UK tables](https://design-system.service.gov.uk/components/table/), [W3C tables tutorial](https://www.w3.org/WAI/tutorials/tables/), [GOV.UK details](https://design-system.service.gov.uk/components/details/), [GOV.UK tabs](https://design-system.service.gov.uk/components/tabs/), [ONS chart selection](https://service-manual.ons.gov.uk/data-visualisation/chart-types/choosing-a-chart-type).

### Example

A library page helps visitors choose a branch that is open on Sunday. Each branch has a labeled row, with Sunday hours aligned under the same column. An advance-booking condition appears beside the hours it qualifies. FMT-04 applies if visitors also need to compare a second field, such as available services. The table can pass FMT-09 for the booking condition even if policies and directions remain in a separate disclosure.

## Test with first-time readers

Use RES-06 and RES-07 in the [main checklist](checklist.md#testing-with-the-target-audience) to measure whether first-time readers can identify the view's purpose and find or interpret information without a tutorial. These tests require observations from the target audience. Set the starting view, neutral prompt, accepted answers, exposure or task time, and pass threshold in advance. A sample prompt for a read-only page is “Does this price require a yearly commitment?” It names the fact to find without naming the component or location. Record wrong answers and missed conditions separately from timeouts. [GOV.UK moderated usability testing](https://www.gov.uk/service-manual/user-research/using-moderated-usability-testing).
